# Fusion 360 建模 Skill 通用化评估与优化方案

日期：2026-10-30  
状态：已实施第一轮改造；真实建模与跨客户端验收待完成。  
范围：初始评估覆盖 Skill、参考文档、两个 Python 脚本、发布 zip 与本地 CodeBuddy 安装副本。下文问题表保留改造前的审查结果，当前进展见末尾实施记录。

## 1. 结论与建议定位

现有 Skill 已具备值得保留的基础：参数规划、分步执行、几何测量与图像检查分工、错误分类，以及按需加载的 references 结构。正式 Skill 已去除 DeepSeek 模型绑定，CodeBuddy 的直接绑定主要出现在 README 安装说明中。因此，通用化不需要推倒重写。

**建议定位：面向支持 Skill 指令与工具调用的 AI 客户端，通过可用的 Fusion 360 连接能力完成参数化实体的创建、修改、检查与交付。**

需要拆开的实际上是四类依赖：

| 层次 | 当前情况 | 建议目标 |
|---|---|---|
| AI 客户端 | 只说明 CodeBuddy 安装方式 | 共享一份 Skill；各客户端单独说明安装、MCP 配置与图像交付方式 |
| 模型能力 | 已区分有无视觉，但假设截图始终可取得、可交付 | 根据工具、客户端和模型的实际能力选择验证方式 |
| Fusion 连接方式 | 核心直接绑定某个适配器的 4 个工具与固定端点 | 核心描述所需能力，适配说明保存真实工具名、参数、返回结构和限制 |
| 建模与制造场景 | 通用实体建模默认套用 FDM 规则 | 先完成 CAD 几何验证；用户有制造需求时再加载对应工艺规则 |

第一版应优先实现“同一个 Fusion 适配器可被多个客户端使用”，再根据真实需求接入第二种适配器。暂不扩展成跨 CAD 软件平台，也不承诺自动支持所有 MCP 服务、复杂曲面、装配运动或 CAM 加工。

## 3. 优先解决的问题

优先级定义：P0 为可能误改模型、误判结果或放过非法输入；P1 为直接影响通用性、效率和维护；P2 为增强交付与扩展能力。

### 3.1 P0：报错后无条件 undo，无法保证只撤销失败步骤

依据：`SKILL.md` 的全局规则、`error-recovery.md` 的通用原则，以及 `mcp-tools.md` 的 undo 说明。

仓库同时写了“undo 撤销最近一次已提交事务”和“几何报错时只撤销当前这一步”。这两个描述不能直接等同：如果调用在创建前失败，可能没有新事务；如果失败前已部分修改，可能留下不同范围的变化；如果用户期间手动操作，最近事务也可能属于用户。一次脚本调用也不天然等于一次 Fusion 事务。

建议：

1. 修改前记录目标文档、组件、相关实体与特征状态；有时间线时记录时间线位置和数量。
2. 失败后先只读检查，区分未修改、已完成、部分修改和状态未知。
3. 仅在适配器事务语义已验证、且能确认撤销目标属于本次操作时使用 undo。
4. 无法确认时停止后续修改，报告已知状态，不猜测性回滚或清空文档。
5. 超时也按“结果未知”处理：先检查操作是否已完成，再决定是否重试，避免重复创建。

### 3.2 P0：毫米约定没有覆盖 Fusion API 的内部单位

依据：主 Skill 要求全部使用 mm；错误文档提到单位混用，但没有形成统一的 API 输入与测量输出转换规则。

Fusion API 常见内部长度单位为 cm、角度为 rad，体积相应为 cm³；具体参数和返回值仍应以目标 API 文档为准。只把界面单位设成 mm，不能让脚本中的所有数值自动变为 mm。

建议增加单位边界说明：

- 用户输入保留原始单位，内部规划可统一换算为 mm。
- 支持单位表达式的 API 优先使用带单位表达式；必须传裸数值时显式转换。
- 所有测量结果都携带单位，比较前统一量纲；不能把体积数值当成 mm³ 直接输出。
- 把设计尺寸公差、数值比较容差、制造补偿分开，避免用同一个阈值处理三种问题。
- 用“用户要求 40 mm，实际模型长度为 40 mm”做端到端验收，不能只检查输出标签。

### 3.3 P0：几何检查的证据与结论不匹配

依据：`visual-verification.md` 的无视觉降级策略写有“体包围盒相交 + 体积校验”判定干涉；`3d-print-rules.md` 建议用面距或包围盒差检查最薄处。

包围盒相交只能筛选可能相交的对象。两个实体包围盒重叠、各自体积均为正，并不能证明实体发生干涉。包围盒差也不能普遍证明复杂零件的最小壁厚。

建议将证据明确分级：

| 检查目标 | 可接受的依据 | 结论边界 |
|---|---|---|
| 总体尺寸 | 指定坐标系中的尺寸测量、包围盒 | 能验证外部范围，不能替代孔径、孔深与壁厚 |
| 孔径、孔距、位置 | 对应特征参数与实际几何测量 | 参数值和最终几何应相互核对 |
| 实体干涉 | 可用的 Fusion 干涉分析或经过验证的实体求交方法 | 包围盒只做初筛；区分接触与体积重叠 |
| 壁厚 | 适合目标几何的局部测量或受支持的厚度分析 | 抽查必须报告位置与覆盖范围，不能声称全局最小值 |
| 草图约束 | API 返回的约束状态和必要的自由度检查 | 图片无法证明完全约束 |
| 特征健康 | 特征状态、错误/警告信息、重计算结果 | “工具调用成功”不等于“模型健康” |
| 外观与方向 | 真实模型截图 | 不用于证明尺寸精度或内核拓扑有效性 |

报告状态至少区分：通过、不通过、未验证、不适用。缺失能力时允许交付已完成部分，但不能把“未验证”写成“通过”。

### 3.4 P0/P1：参数校验器有已复现的漏检与异常

以下结果来自本次对 `validate()` 的离线调用，不涉及 Fusion：

| 输入情况 | 当前实际结果 | 建议行为 |
|---|---|---|
| `hole_dia_mm: -3` | 无 error，仅 warning；按 CLI 逻辑退出码仍为 0 | 直径必须大于 0，返回结构化错误 |
| `hole_dia_mm: "large"` | 无 error、warning，数值检查被跳过 | 数值字段拒绝任意字符串；若支持表达式，单独声明并解析 |
| `step: true` | 无 error、warning | 明确拒绝布尔值作为整数序号 |
| 特征顺序为 `[2, 1]` | 无 error、warning | 如果数组代表执行顺序，应拒绝倒序；不要静默重排依赖 |
| `process: 123` | 抛出 `AttributeError` | 返回字段类型错误，维持稳定报告结构 |
| `process: "CNC"` | 回退成 FDM，并输出提示 | 不应把未知工艺自动当打印；执行通用检查并标记工艺未覆盖 |

现有检查依赖字段名称片段，例如 `dia`、`wall`，不能表达真正的参数语义。后续应分两层：结构校验负责类型、必填项、有限数值和步骤依赖；领域校验负责孔径、厚度、数量、配合等关系。坐标和偏移可以为零或负值，直径和实体厚度通常不可以，不能一律按“正数”处理。

### 3.5 P1：核心绑定了特定 MCP 适配器

依据：`SKILL.md` 开篇写死 4 个工具、脚本入口、执行方式和服务端点。

建议保留当前真实适配器的详细说明，但让核心先识别当前宿主实际提供的工具与 schema，再选择已知的适配说明。**名称相近不能证明语义相同；动态发现不等于自动兼容任意服务。**

核心只约定读取文档、读取目标几何、执行修改、测量、截图、恢复和交付等能力。工具名、传参方式、`run(_context)`、`readOnly`、返回内容解析、undo 事务语义全部属于适配器层。

现有端点可保留为该适配器的示例默认值；运行时优先复用宿主已连接的工具。没有本地 shell 的客户端不能被迫运行 Python 探测脚本；运行在远端的代理访问 `127.0.0.1`，也不代表访问用户桌面的 Fusion。

### 3.6 P1：流程对所有任务施加同一种交互成本

依据：每个特征查 API、建模、测量、截图，再等待用户确认；每轮限制一张截图。

这适合逐步教学，却会让已授权的普通建模反复中断。以 N 个特征为例，现流程约需至少 4N 次工具调用，另加实体读取和准备工作，并产生 N 次逐步确认；已核对过的 API 也重复查询。

建议提供三种轻量执行模式，不必构建复杂配置系统：

| 模式 | 适用情况 | 执行方式 |
|---|---|---|
| 自主执行，默认 | 目标清楚，用户已授权建模或修改 | 在授权范围内连续执行，内部保留检查点，关键阶段汇报 |
| 逐步确认 | 用户要求教学、观察或逐步控制 | 在约定步骤停下，等待用户反馈 |
| 仅规划 | 用户要求先出方案，或当前缺少执行能力 | 输出参数、特征计划、假设和验证方法，不修改模型 |

模型检查仍必须执行；减少的是不必要的用户确认与重复调用。缺少影响配合、承载或关键尺寸的信息时，需要澄清；外观等低影响细节可以记录假设后继续。

第一版继续保留保守的小步执行即可。只有在适配器执行和恢复行为经测试后，才考虑把依赖紧密、风险低的操作组成一个可检查步骤；不以减少调用数为理由批量生成整个复杂模型。

### 4.2 主 SKILL.md 的职责

建议只保留：触发范围、任务类型判断、能力检查、必要的参数规划、分步执行与验证、失败恢复入口、结果交付，以及各参考文件何时读取。

建议描述草案：

```yaml
name: fusion360-mcp-cad
description: 通过可用的 Fusion 360 工具创建、修改和检查参数化实体模型，适用于机械零件、外壳、支架与 3D 打印零件；在需要实际 CAD 几何、尺寸验证或模型交付时使用。
```

暂不改名，避免破坏已有安装和引用。删掉描述中的执行细节和重复触发词；不要默认加载全部 references。打印规则只在打印任务读取，适配器说明在识别到对应服务时读取。

### 4.3 客户端适配只处理接入差异

客户端指南应分别记录 Skill 加载方式、MCP 连接方式、图像内容传递、脚本执行环境和验证版本。Skill 安装成功不等于 MCP 已连接，MCP 已连接也不等于模型能看到截图。

| 接入目标 | 本次证据 | 后续需要验证 |
|---|---|---|
| CodeBuddy | 仓库已有安装说明，本地安装副本与源文件一致 | 实际加载、工具调用、截图和完整建模流程 |
| Codex | 候选适配客户端，尚未实测本 Skill | 当前版本的 Skill 加载、MCP 配置及图片传递 |
| Claude Code | 候选适配客户端，尚未实测 | 同上，并核对目录和配置约定 |
| Cursor 或其他 MCP 客户端 | 候选接入目标，是否原生支持此 Skill 形式需核对 | 原生 Skill 加载或显式指令入口，以及真实工具能力 |

本方案不把某个客户端的目录或 JSON 配置格式当成通用标准。实施时核对各客户端当前文档并记录实际版本；没有原生 Skill 支持的客户端，可提供明确加载核心说明的方式，但应标明不能保证自动触发。

### 4.4 能力识别与降级

会话开始只检查当前任务需要的能力，避免读取无关项目和许可信息。至少确认目标文档可读、目标实体可识别、是否可修改、是否能执行必要几何检查；按任务补充截图、导出和恢复能力。

- 工具不存在或无法连接：完成规划，说明缺少什么能力，不声称已建模。
- 无截图工具：继续可完成的数值检查，标记外观未验证。
- 截图存在但模型看不到图像：可以向用户展示，模型不能编造视觉结论，也不必因此每步暂停。
- 无干涉或厚度分析：报告可验证的指标和覆盖范围，不用包围盒结论冒充完整检查。
- 无可验证的恢复方式：缩小操作步长；发生部分失败时先检查状态，不自动连续撤销。

### 4.5 MCP 接口定义优先使用实时信息，适配文档按需保留

**完整的 MCP 接口定义文档不是 Skill 的必需文件。** 正常连接 MCP 后，宿主客户端会发现工具，并在模型需要时提供工具名称、描述和参数 schema；具体发现和加载方式取决于客户端。Skill 不必再维护一份相同的参数表、必填字段和枚举列表，避免重复加载和文档过期。

需要区分两层接口：MCP 工具定义说明如何提交、读取和执行操作；脚本中的 `adsk.core`、`adsk.fusion` API 通常不包含在 MCP 参数 schema 中。即使执行工具只接收一个 `script` 字符串，编写脚本时仍可能需要按需查询具体 Fusion API 的签名、单位和行为。

后续完善 `mcp-tools.md` 时，按以下原则取舍：

| 信息 | 优先来源 | 文档处理方式 |
|---|---|---|
| 工具名称、参数、必填项、枚举 | 当前连接提供的工具 schema | 删除重复定义，不把历史快照当调用依据 |
| 脚本入口、输出返回方式、只读限制 | 工具描述或服务提供的相关资源 | 仅补充实际缺失且已核实的约定 |
| 事务边界、undo 行为、超时后的状态检查 | 服务说明与真实环境验证 | 保留 schema 未表达的限制，标明适用适配器与验证范围 |
| Fusion API 方法、属性与单位 | 可用的 API 文档查询能力或官方文档 | 按需查询，不复制整套 API 手册 |
| 建模方法、几何验证与能力降级 | 核心 Skill 和对应专项参考 | 独立维护，避免与适配器说明重复 |

具体改造项：

1. 将该文件精简为“当前 Fusion MCP 适配注意事项”；是否改名以维护引用便利为准。
2. 删除重复参数表、完整枚举，以及电子设计、购买、PPT 等与实体建模无关的说明。
3. 只保留工具定义未覆盖的执行约定、已验证限制和恢复注意事项；识别到该适配器且确有需要时才读取。
4. 若工具描述和可读取的服务资源已完整覆盖上述信息，允许删除该文件，并同步更新 `SKILL.md`、README 和资源索引。
5. 如需记录 schema 快照用于版本比较，将其作为维护与诊断资料，不默认加载为模型运行指令。

建议写入核心 Skill 的规则：

> 工具名称与参数以当前连接提供的 schema 为准；Fusion API 按需查询。适配文档只补充实时工具定义未覆盖的使用约定与已知限制。信息冲突或关键语义不明确时，先核对当前服务行为，不按历史文档猜测执行。

本项纳入后续统一改造，本次不直接精简或删除现有接口文档。

## 5. 建模规则应如何调整

| 当前规则 | 建议规则 |
|---|---|
| 所有任务使用 mm | 用户单位优先；统一内部计算单位并显式转换 |
| 默认 XY 和世界原点 | 新建简单零件可用默认基准；修改现有模型时遵循现有组件、局部坐标与设计意图 |
| 必须完全约束草图 | 参数化驱动轮廓优先完全约束；导入参考、投影、样条等按用途检查并说明剩余自由度，避免仅靠全固定伪装参数化 |
| 圆角一律最后 | 装饰性圆角优先最后；影响抽壳、后续轮廓或功能的圆角按依赖顺序创建 |
| 尽量不用放样、扫掠 | 依据形状选特征；复杂特征增加验证，不因工具类型一概否定 |
| Join/Cut 一律预留 ≥ 0.01 mm | 根据具体几何、容差和 API 要求处理重叠；优先使用到面、贯穿等适当终止方式，不擅自改变设计尺寸 |
| 任何脚本前重新查 API | 首次使用或签名不确定时查文档；复用同一环境中已核对的信息，版本变化或报错时重新核对 |
| 禁止所有 try/except | 不吞异常；是否允许清理后重新抛出取决于适配器真实约定，不能把经验写成服务端强制限制 |
| 固定 temperature 0.1–0.2 | 从建模核心移除；这通常属于宿主设置，Skill 不应假定可控制模型采样参数 |
| 每步一张固定等轴测图 | 在关键阶段和外观变化后截图；孔位用正投影，内腔按需剖视，截图数量由检查需求决定 |

还应补充两个现有薄弱点：

**参数化不只是按尺寸画出形状。** 关键尺寸应形成可编辑的用户参数和表达式依赖；修改参数后应能重计算并检查健康状态。记录“外宽改变后，孔仍保持距边 5 mm”这样的设计意图，比只记录第一次建模的坐标更有用。

**修改现有模型需要单独路径。** 先确定文档、组件、实体及目标特征，再选择修改原参数或新增特征；区分有历史时间线的设计与导入实体。不要依赖 `bodies.item(0)`、固定面序号或名称唯一性。实体 token 等引用应按 API 规则解析并重新确认有效性，不能假设字符串永远稳定。装配实例还要明确本地坐标与装配坐标的转换。

## 6. 打印规则的边界修订

现有打印文档可以保留，但默认值应带适用条件，且不能自动成为模型验收门槛。

- 壁厚与线宽、喷嘴、材料、层高和受力相关；“0.4 mm 喷嘴对应 1.2 mm 壁厚”可作为起点，不能证明所有打印件合格。
- 悬垂判断需说明打印朝向、朝下表面、角度定义和桥接条件；不能只用一个角度阈值判断所有面。
- 拔模主要服务脱模或特定结构需求，不应作为所有 FDM 深腔的通用要求。
- “圆角半径不超过最短边的一半”只能作为粗略经验，不能作为通用可行性判据。
- 区分螺钉过孔、自攻底孔与热熔螺母安装孔，不能混用直径规则。
- 配合必须说明单边/直径间隙和正负方向；正间隙不能直接称为压配过盈量。
- 大尺寸件统一补偿 0.5%–1% 缺少材料和设备条件，应改为按工艺标定值补偿。
- “螺柱高度不超过壁厚 3 倍时需加支撑环”的条件值得复核，不能沿用为硬规则。

未知工艺默认执行通用 CAD 检查。只有用户声明打印用途时才加载打印建议；其他工艺可后续增加经过验证的专项参考，不要通过名称自动猜测其制造约束。

## 7. 脚本改造与结果交付

### 7.1 MCP 探测脚本

已离线复现：模拟 `tools/list` 返回 JSON-RPC `error` 时，`list_tools()` 返回 `([], "")`，丢失错误；多行 `data:` 组成的单个 SSE 事件解析为空。源代码还显示：未处理 `tools/list` 分页、未携带协商版本用于后续 HTTP 请求、读取完整 SSE 响应体后才解析，且 `--tools` 列举失败时退出码仍只取决于 initialize 是否成功。

建议优先修复：

1. 区分连接成功、初始化成功、工具发现成功与建模能力满足；按请求目标定义退出码。
2. 保留 JSON-RPC 错误码与消息，不把错误转换为空工具列表。
3. 正确处理版本协商、会话头、工具分页、SSE 事件边界及读取超时；不要静默忽略初始化通知失败。
4. 优先评估维护中的 MCP SDK；若继续使用标准库，明确支持的协议范围并增加对应协议测试。
5. 默认报告避免暴露会话标识；认证信息由宿主或明确配置提供，日志不记录凭据。

当前工具适合诊断 HTTP 端点，不能据此声称支持 stdio 或所有远程连接方式。第一版不必自行重写完整 MCP 客户端，宿主已有连接能力时应直接复用。

### 7.2 参数校验脚本

优先补齐已复现的错误，再按真实建模需求扩展参数契约：显式类型、量纲、约束、目标引用和步骤依赖。报告区分非法输入、工艺提醒、未覆盖检查。未知字段应保留并提示，不能因未识别就视为已验证。

如果后续采用版本化 JSON 格式，可增加 `schema_version`、输入单位、命名参数、目标组件、步骤依赖和验收条件；先覆盖现有常用特征，避免提前构建一个抽象 CAD 编程语言。

### 7.3 完成标准与交付

“工具成功返回”不应是任务完成标准。至少交付：

- 当前模型所在文档、关键组件与实际完成的特征。
- 关键参数、验收结果，以及未验证项目和影响。
- 保存状态；用户要求导出时，列出实际生成的文件与路径。
- 必要的视图和工艺建议，避免逐条堆叠全部 MCP 日志。

保存和导出按用户请求及工具实际约束执行，不强制每次都保存，也不把有权限执行的交付动作反复拦住。已有同名文件、云端目标或关闭未保存文档涉及实际选择时，再处理具体冲突。可编辑模型、STEP 和 STL/3MF 的用途不同，不能默认把网格当成可编辑参数化模型；网格导出还应核对单位和离散精度。

## 8. 实施顺序与验收

### 阶段 A：先修正确性

修改单位约定、错误恢复、几何验证结论和参数校验器；修复 HTTP 探测脚本的已复现问题。现有工具名称与文件路径先保持不变，降低迁移成本。

验收：非法孔径和类型明确失败；未知工艺不回退到 FDM；未发生修改的报错不触发 undo；没有精确干涉证据时不报告干涉检查通过。

### 阶段 B：完成客户端通用化

精简主 Skill，隔离当前适配器说明；按第 4.5 节移除重复接口定义，评估是否还需要独立的 `mcp-tools.md`；增加自主执行、逐步确认、仅规划的路由；更新 README 和客户端接入指南。保留 CodeBuddy 入口，新增至少一个实际验证过的其他客户端。

验收：两个客户端使用同一份核心 Skill，分别完成同一个简单零件与一次参数修改；工具调用使用当前 schema，适配文档仅包含必要补充且所有引用有效；记录客户端、Fusion、适配器版本和工具 schema，不能仅靠安装成功宣称兼容。

### 阶段 C：补齐交付与发布

完善保存、导出、检查报告和必要的可复用脚本示例；将历史草稿移出运行入口；建立源码与 zip 的一致性检查。只有出现第二种真实连接需求时才增加适配器目录和兼容逻辑。

验收：发布包从唯一源码生成，解压内容与源码一致；客户端安装副本可追溯到版本；文档中的每项“已支持”都有实际检查记录。

### 建议验收场景

| 场景 | 应观察到的结果 |
|---|---|
| 创建 40 × 20 × 5 mm 带孔板 | 尺寸正确、孔径与孔距有测量证据，无多余实体 |
| 输入英寸尺寸 | 实际几何换算正确，报告保留清晰单位 |
| 将外宽从 40 改为 50 mm，孔距边保持 5 mm | 参数依赖生效，不重复创建零件 |
| 当前文档有两个相似实体 | 明确目标，另一个实体未被误改 |
| API 调用在修改前报错 | 不撤销前一步成功特征 |
| 修改已完成但响应超时 | 查询后识别完成状态，不重复创建 |
| 用户手动切换文档或修改几何 | 重新核对上下文，不沿用失效引用 |
| 无视觉、无截图或缺少厚度分析 | 继续可完成部分，缺失检查标记为未验证 |
| 有空腔且包围盒重叠的两个不相交实体 | 不仅凭包围盒误报干涉 |
| 用户只要求方案，或只要求检查 | 不创建或修改几何 |
| 请求模型文件交付 | 文件真实存在，格式、单位和保存状态可核对 |

其中脚本结构和协议问题可离线测试；涉及 Fusion 几何、事务、截图和保存的场景必须在真实环境完成。测试失败时记录实际限制，不能靠措辞把未验证能力写成兼容。

## 9. 建议采用的第一版改造范围

建议下一步实施“阶段 A + 阶段 B”，以修复误判风险和共享核心为主。保留现有 Skill 名称与已记录适配器，不引入复杂插件框架，不同时铺开所有工艺与客户端。

完成这一版后，用户应能在已验证的不同 AI 客户端中复用相同建模规则；清楚授权后能够连续完成建模；遇到能力不足或失败时知道哪些结果可信、哪些需要补查，而不是依赖每步确认来弥补执行可靠性。
