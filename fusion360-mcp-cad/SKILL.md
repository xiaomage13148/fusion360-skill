# Fusion 360 参数化实体建模

## 任务与执行模式

先判断用户需要创建、修改、检查，还是仅规划；只检查的任务不修改几何。

- **自主执行（默认）**：用户已授权、目标清楚时，简述参数与步骤后连续完成；保留内部检查点，在关键阶段汇报，无需每个特征重复确认。
- **逐步确认**：用户要求教学或逐步控制时，按约定步骤等待反馈。
- **仅规划**：用户要求先出方案，或缺少执行工具时，交付参数、假设、建模顺序与验证方法，不声称已创建模型。

影响配合、承载或关键尺寸的信息缺失时先澄清；非关键细节可采用明确标注的假设。用户已授权的常规操作不额外增加确认步骤。

## 能力与接口

优先使用宿主已连接的 Fusion 工具，按当前任务确认：文档与目标可读、是否可修改、可用的测量和健康检查能力；按需检查截图、恢复和导出能力。不要为确认连接读取无关项目或许可信息。

工具名称、参数与限制以当前连接提供的 schema 和描述为准，不从旧文档猜测。MCP 脚本工具的 schema 不等于整个 Fusion API 文档；首次使用或签名不确定时查询相关 API，复用同环境已核对的信息，遇版本变化或报错再核对。

识别到 `fusion_mcp_read` / `fusion_mcp_execute` 风格的适配器、且实时说明不足时，读取 [适配注意事项](references/mcp-tools.md)。其他服务需确认等价语义，不能仅凭工具名称相近就调用。

没有截图或图像理解能力时继续数值检查，标记外观未验证；缺少必要的几何检查时明确覆盖范围。无修改能力时仍可完成规划或检查。可选 HTTP 诊断脚本是 `scripts/check_mcp_server.py`，不是建模前必须运行的步骤；远端环境的 localhost 不代表用户桌面。

## 建模闭环

创建或修改前读取 [参数、单位与实体引用](references/modeling-and-units.md)；只有需要校验参数 JSON 时才读取 [参数格式](references/parameter-format.md) 并使用 `scripts/validate_part_params.py`。

1. **确定上下文**：核对活动文档、组件/装配实例、目标实体、设计历史模式、单位和交互命令状态。修改已有模型时保留其坐标与设计意图。
2. **规划依赖**：列出关键尺寸、公差、可编辑参数及特征顺序。优先修改已有参数或目标特征，避免重复创建。装饰圆角通常靠后；功能特征按实际依赖安排。
3. **记录检查点**：读取目标特征、实体与关键测量；有时间线时记录位置和数量。检查点用于比较状态，不代表事务快照或可自动恢复的保证。
4. **小步修改**：默认每次修改调用处理一个可独立检查的建模特征，草图和拉伸分开。一次调用不天然等于一次事务；不把整个复杂模型塞进单次脚本。对同一文档的修改串行执行。
5. **独立验证**：修改后重新读取实际几何与特征健康状态，核对尺寸、数量及设计意图，再继续依赖步骤。新错误或异常按 [失败恢复](references/error-recovery.md) 处理，禁止无条件 undo 或超时后直接重发修改。
6. **阶段质检**：主体、关键开孔、内腔或外观完成后，按 [验证规范](references/visual-verification.md) 选择测量与视图；截图辅助外观判断，不能证明精确尺寸、全局壁厚或实体无干涉。

草图驱动尺寸优先用参数和几何约束表达；不要靠固定全部图元伪装参数化。根据形状选择拉伸、孔、阵列、扫掠或放样，复杂特征加强局部检查。布尔操作依据实际几何与 API 条件执行，不用统一的微小重叠量擅自改变设计尺寸。

## 结果与交付

验证项目使用 **通过 / 不通过 / 未验证 / 不适用**，注明依据、单位、容差和覆盖范围。包围盒只证明外部范围；干涉和全局最小壁厚需要相应证据。

用户声明打印用途时才读取 [3D 打印建议](references/3d-print-rules.md)，将经验值与几何硬约束分开。未指定工艺时不默认套用 FDM 规则。

交付目标文档、实际完成的特征、关键参数、检查结论和剩余限制。按用户请求及工具约束保存或导出，检查文件真实存在、格式与单位正确，并说明保存状态；已有文件冲突或未授权丢弃修改时处理具体选择。原生参数化模型、STEP 与网格的用途不同，不以 STL 代替可编辑模型。

自主执行模式汇报关键结果与下一步即可；逐步确认模式再逐步展示操作、结果、测量和计划。保留关键诊断，不回灌整段日志或 base64。
