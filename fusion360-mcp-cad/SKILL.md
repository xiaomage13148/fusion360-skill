# Fusion360 MCP 参数化 CAD 建模

## 概述

通过 MCP 协议驱动 Fusion360 完成参数化实体建模。该 MCP 服务只暴露 4 个通用工具（`fusion_mcp_read` / `fusion_mcp_execute` / `fusion_mcp_update` / `fusion_mcp_electronics_read`），**全部实体建模操作都通过 `fusion_mcp_execute` + `featureType: "script"` 执行 Python 脚本完成**。核心约束：**一段脚本只创建 1 个 CAD 特征**，每个特征完成后立即做测量校验与视觉自检，确认无误才进入下一步。特征类型以草图、拉伸、打孔、阵列、偏移为主，规避放样与复杂曲面等易崩坏拓扑，面向 3D 打印零件设计。

## 模型能力分级（重要）

本 skill 不绑定特定模型，按当前模型是否具备图像理解能力自动选择校验通道：

| 模型能力 | 校验策略 |
|---|---|
| 视觉多模态模型 | 双通道校验：MCP 测量数值 + 视口截图图像分析，自动输出视觉自检结论 |
| 纯文本 / 仅工具调用模型 | 降级单通道校验：仅依赖测量脚本输出的数值结论；截图仍然捕获并附上，交由用户人工确认 |

两种模式**建模流程完全一致**，只有图像分析环节按能力降级。禁止因无视觉能力而跳过测量校验，也禁止用图像替代几何内核校验。

## 全局建模铁律（永久生效）

1. **单位**：全部使用毫米 (mm)；除用户明确指定外，草图默认建立在 XY 基准平面，草图原点优先使用世界原点。
2. **单特征执行**：单次 `fusion_mcp_execute` 调用（即一段脚本）只能创建 1 个 CAD 特征。禁止在一段脚本中批量创建多个草图、拉伸、布尔或圆角。
3. **草图规范**：草图必须完全约束；优先使用原点定位；避免共面与微小重叠面，防止布尔计算失败。
4. **时序铁律**：主体实体 → 切除/打孔/阵列 → 最后统一添加圆角/倒角。圆角禁止提前创建。
5. **实体选择**：执行操作前先在脚本中读取并 `print` 当前文档实体列表，确认目标 Body/Component，防止误选旧几何体；多零件推荐分 Component 管理。
6. **布尔规则**：Join/Cut 必须保证实体存在明确重叠，预留 ≥ 0.01 mm 重叠量；分步布尔，禁止一次性多实体合并。
7. **失败处理**：几何报错时用 `fusion_mcp_update` + `featureType: "undo"` 仅撤销当前这一步，保留前面所有已完成实体；输出错误诊断，不要清空整个文档。
8. **特征偏好**：优先使用草图、拉伸、打孔、阵列、偏移；尽量少用放样、边界混合、复杂曲面扫掠，这类拓扑极易崩坏。

## 三阶段建模流程

### 阶段 1：需求解析与参数规划

- 接收零件需求，输出【参数表 + 分步建模大纲】。
- **此阶段不调用任何 MCP 建模命令**，只输出规划，等待用户确认后再进入建模阶段。
- 参数不明确时给出合理默认值并显式标注假设，不因细节缺失阻塞流程。

### 阶段 2：分步建模 + 单步闭环校验

每个特征严格走固定闭环：

1. 先查 API 文档（`fusion_mcp_read` + `queryType: "apiDocumentation"`），再用 `fusion_mcp_execute` + script 创建**单个**特征；
2. 单独调用一次脚本（**设 `readOnly: true`**），读取实体尺寸并 `print` 输出（包围盒、体积、关键尺寸）；
3. 调用 `fusion_mcp_read` + `queryType: "screenshot"` + `direction: "iso-top-left"` 捕获正交等轴测视图（截图前关闭基准面、草图标记，画面只保留实体）；
4. 分析「测量数值 + 截图图像」，输出自检报告；
5. 输出自检结论，等待用户确认后才允许进入下一个特征；用户不确认，禁止继续。

视觉检查清单与自检报告模板见 `references/visual-verification.md`。

### 阶段 3：模型收尾与质检

1. 全部主体特征完成后，统一添加圆角/倒角；
2. 用脚本执行干涉检查（Body 相交判定）与壁厚抽查，并 `print` 结果；
3. 输出最终模型质检报告，给出 3D 打印建议。

3D 打印专项规则见 `references/3d-print-rules.md`。

## 工具调用约束

- 采样温度固定 0.1~0.2（模型/客户端可配置时），保持工具调用稳定、可复现，禁止高随机性。
- 编写任何建模脚本前，先用 `fusion_mcp_read` + `queryType: "apiDocumentation"` 查清目标 API（类、方法、属性、枚举），禁止凭记忆手写 `adsk.fusion` 调用。
- 脚本内不要用 try/except 捕获异常，让报错信息完整暴露，便于诊断与回退。
- 测量/检查脚本一律设 `readOnly: true`（命令对话框打开时也可运行）；建模脚本不设该参数——若用户正处于草图/拉伸等命令中，先请其关闭对话框再执行。
- 禁止在同一次工具调用中混合规划、建模、截图、测量多个任务。
- 单轮对话最多 1 张截图，避免图片膨胀上下文；零件完成后建议新开对话，隔离历史图片与 MCP 日志。
- 开始建模前先确认 Fusion360 MCP 服务在线（端点 `http://127.0.0.1:27182/mcp`），可用 `scripts/check_mcp_server.py` 探测连通性。
- 工具清单、参数约定与推荐调用顺序见 `references/mcp-tools.md`；调用前以服务实际返回的 schema 为准。

## 输出格式约定

每一步输出保持固定结构：

```
1. 当前步骤编号
2. 本次要执行的操作简述
3. MCP 执行结果
4. 测量数据
5. 视觉自检结论（无视觉能力模型标注「数值校验」）
6. 下一步计划（等待用户确认才执行）
```

## 失败与异常处理

出错时先分类再修复，禁止盲目重试整套流程。常见错误（草图未约束、圆角超限、布尔失败、命令对话框阻塞、脚本 API 误用、MCP 掉线）的诊断与修复策略见 `references/error-recovery.md`。
